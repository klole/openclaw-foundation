# Runnable foundation services

These engines ship with the archive and read installation configuration. Each model turn runs in a fresh native session. File requests are documented in backend.md. Public delivery, web, browser, shell, cron and gateway tools are excluded from generated seats. The operator CLI is the authorization boundary; run it only as the trusted host operator. Host root access is outside agent role permissions.

| Engine | Built-in behavior and proof |
|---|---|
| Delegation | COS brief → maker artifact/evidence → distinct checker → bounded FIX loop → COS close; fixture completes after a rejected first output |
| Builder/trainer | Frozen brief/context, dependency proofs, task size, role/tests, release challenge, judge, change review, canonical role install, explicit activation, held-out native onboarding |
| Research | Answer/compare/plan over frozen saved sources; research angles → quote/number/arithmetic checks → judge → breaker → director/challenger → readiness; plans add code gate, fresh verifier turns and release challenge |
| Context/Bible | Read-only fact exports, recorded/collected conflict handling, last known stale facts, dated history, goal packets, keeper note/proposal bridge and independently reviewed canonical filing |
| Change/merge gate | Configured literal-argument repository checks on a clean exact head, independent review, current owner authorization, independent GitHub merger identity and match-head merge; real merges are explicit operator commands |
| Monitor | New/stalled job and unreadable source incidents route once; observed fresh success verifies recovery; lost leases require operator inspection/retry |
| Wake/scheduler | Adaptive seven-level ladder; idle specialists stop, control seats do not independently wake, managers wait for approved plans, active work prevents overlaps; recurring work/research requests have stable cadence keys |
| Budget guard | Reserve before call; per-day/job turn caps, token reservations, closed paid-call brake, deadlines, retry/backoff and bounded research rounds; provider billing/output limits remain a target responsibility |
| Hygiene/HQ/recovery | Archive old memory/notes without discarding originals; flag oversized goal sheets for keeper reconciliation; escaped local HQ; private checksummed application backup and fresh-destination restore |

The backend makes no assumption that a named platform tool exists. JSON fact exports and saved research sources are the generic adapters. Company-specific credentialed platform adapters, paid search, browser use, notification channels, public actions and cross-company routing are configured/proven separately. A company can start with these engines without registering itself in the original house's fixed business tables.

Lifecycle limitations are deliberate and visible: a helper is built only after its exact proposal is covered by the parent build sign-off, a passed change review does not merge a PR, a rendered role does not pass onboarding, and a source gap does not become a verified fact. Archive/release a local agent through a reviewed local customization; retain its role, work and reason. Existing house-only dashboards, billing integrations and platform workflows are not copied.
