# Hire and change route

1. Owner or manager supplies an exact brief. COS checks the directory for an existing role and distinguishes a change, a new agent or a new team.
2. Trainer preserves the brief verbatim and makes a requirements checklist. A team or an unspecified roster needs a team design card: goal, seats, parents, agent vs script, front doors, tools, terms, costs and owner decisions.
3. Independent release challenger tests the design. COS handles internal scope decisions; owner approval covers the new team/seats and any costs or accounts. Record scope, payload and expiry; silence is not approval.
4. Obtain a current context packet. List tool dependencies; hold the affected build until each has a proof or an explicit unresolved access request.
5. The builder sizes the work with the judge. Research complex roles through a saved-source research job before approving the build; the portable size result alone is not a completed role research run. Trainer writes the small core role and on-demand playbooks; held-out tests are evaluated independently by the release gate and judge.
6. Required approval, reviewed canonical role change, provisioning, first turn, tool proof. When the company board is versioned, submit its role change through the configured repository release/merge gate before activation; portable local role installation is not a GitHub PR. FIX returns to the trainer as a revision of the same build.
7. Trainer reports verified readiness to the COS; COS tells the owner how to try it. A request is not complete merely because files exist.

Manager: learn, obtain context, plan, get plan approval, then execute. Specialist: learn and become ready. Worker: one bounded test assignment. Managers keep a team map. Helpers have a parent and use the same hire route. Trial review yields KEEP, RENEW or RELEASE with reasons; archive released agents rather than deleting their records.

The portable backend uses final owner build sign-off bound to the tested role and exact helper list. Parent activation creates covered helper requests; each still receives independent challenge cases, COS approval and onboarding. New descendants, increased budgets and changed scope require new approval. It retains terms/release criteria as local seat metadata; trial reviews and releasing an agent are operator/COS procedures rather than automatic deletion.
