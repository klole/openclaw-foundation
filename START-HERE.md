# Give this link to your setup assistant

Ask your local Codex, connected Dot or other setup assistant:

> Read this repository's README.md and foundation/template/setup.md. Install the newest eligible packaged release into a fresh private company directory on my Mac or Linux VPS. Use the company-neutral roles and ask me for my company details; do not import the publisher's company. Preserve my existing OpenClaw agents, credentials and gateway settings. Use preview/apply/rollback and show conflicts. Enable daily release notices, while retaining owner-approved installation. Then follow foundation/template/dots.md to configure the HTTPS messaging bridge, create a separate identity for each owner and generate private CONNECT.md instructions. Test the actual host, then help each person connect and authorize their Dot in ChatGPT. Keep passwords and private state out of Git and chat instructions. A receipt is not completion and local tests are not a live Dot proof.

Your assistant needs access to the computer or VPS that will run OpenClaw. A cloud Dot without that access can read these instructions but cannot install a service on an unconnected host. An existing OpenClaw host needs no desktop app to serve the remote messaging connection.

If you are joining someone's existing team, use their private CONNECT.md and your own login instead of installing a second server. Their operator creates your identity; the repository never grants access by itself.

Start with [README](README.md), [company example](foundation/template/company.example.json), [setup](foundation/template/setup.md), [Dots](foundation/template/dots.md) and [updates](foundation/template/updates.md). Published preview candidates await independent review.
